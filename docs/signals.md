# Signals

Dioptase-OS signals are per-user-thread notifications. A parent can send a
signal to one of its live children with `signal_child()`, and the terminal can
send one to the current interactive child with `signal_foreground()`. The
kernel also raises synchronous signals for selected user-mode faults.

The function-call and trap register conventions below follow
`../../docs/abi.md`. Exception entry, EPC, four-byte instruction alignment, and
`rfe` behavior follow `../../docs/ISA.md`.

## Signal numbers

| Number | Name | Maskable | Handler allowed | Kernel-generated meaning |
| --- | --- | --- | --- | --- |
| `0` | `SIGNAL_HELLO` | yes | yes | none |
| `1` | `SIGNAL_TERMINATE` | yes | yes | none |
| `2..15` | reserved maskable signals | yes | yes | none |
| `16` | `SIGNAL_SEG` | no | yes | user TLB permission or mapping fault |
| `17` | `SIGNAL_ILL` | no | yes | invalid or privileged user instruction |
| `18` | `SIGNAL_ALGN` | no | yes | misaligned user PC |
| `19..30` | reserved nonmaskable signals | no | yes | none |
| `31` | `SIGNAL_KILL` | no | no | unconditional termination |

`MAX_MASKABLE_SIGNAL` is the exclusive bound `16`, so only signals `0..15`
may be passed to `mask_signal()` and `unmask_signal()`.

`signal_child()` and `signal_foreground()` accept every number in `0..31`,
including signals normally generated by a fault. Such an explicitly sent
signal is asynchronous and therefore uses the asynchronous handler argument
described below.

## Pending signals and masking

Asynchronous sends set one bit in the target's pending bitmap. Multiple sends
of the same signal before delivery coalesce into one pending instance. Pending
signals are inspected at scheduling boundaries, and the lowest-numbered
eligible signal is selected first.

Masking a signal prevents delivery but does not clear its pending bit.
Unmasking makes a retained pending instance eligible at the next scheduling
boundary. Both masking operations are idempotent. The mask itself is changed
only by the running thread; cross-core senders update the pending bitmap while
holding the target child descriptor's state lock. Locks and the
sequentially-consistent architecture memory model provide the required
atomicity and ordering.

`SIGNAL_KILL` always terminates the target. While a handler is active, maskable
signals remain pending, but any pending nonmaskable signal terminates the
thread. Handlers are never nested.

## Registration and handler ABI

`register_handler(signal, handler)` accepts signals `0..30`. `handler` must be
four-byte aligned, and its complete first instruction must lie in executable
user memory. `SIGNAL_KILL` cannot have a handler.

Handlers run in user mode on a private 4 KiB writable signal stack. The kernel
preserves the suspended kernel activation and the original architectural user
stack pointer while the handler runs.

The first function argument is passed in `r1`:

- An asynchronous handler receives the signal number.
- A kernel-generated `SIGNAL_SEG` handler receives the faulting virtual page
  number. The byte address is `vpn << 12`. `r2` receives the TLB fault flags:
  zero means no TLB entry matched; nonzero bits identify missing permissions.
- A kernel-generated `SIGNAL_ILL` handler receives the faulting EPC, whether
  the cause was an invalid encoding or a privileged instruction in user mode.
- A kernel-generated `SIGNAL_ALGN` handler receives the misaligned EPC.

Handler functions may call ordinary syscalls. To finish, a handler must call
either `sigreturn(rc)` or `exit(status)`. Returning normally, faulting while a
handler is active, or receiving an unhandled nonmaskable signal terminates the
thread.

For an asynchronous handler, `sigreturn()` resumes the context that was
suspended at the scheduling boundary. For a synchronous fault handler, it
restores the exception wrapper's saved EPC, flags, registers, and stack pointer.
The faulting instruction is retried; the kernel does not advance EPC.
Consequently a `SIGNAL_SEG` handler may repair a mapping and retry, while
`SIGNAL_ILL` and `SIGNAL_ALGN` handlers normally call `exit()` unless they can
change state that makes retry valid.

The `rc` argument to `sigreturn()` becomes the return from the nested
kernel-to-user handler activation. It is not injected into the suspended user
register state. Calling `sigreturn()` outside an active handler returns `-1`.

## Default actions and process transitions

An eligible asynchronous signal with no registered handler terminates the
thread with status `-1`. An unhandled `SIGNAL_SEG`, `SIGNAL_ILL`, or
`SIGNAL_ALGN` fault also terminates with status `-1`. A parent observes that
status through `wait_child()`.

`fork()` gives the child a copy of the parent's signal mask and registered
handler addresses, but starts the child with no pending signals and no active
handler. A successful `execv()` preserves the mask and pending bitmap but
clears every registered handler because the old entry-point addresses no
longer name the replacement image. The new image receives a new signal stack.
